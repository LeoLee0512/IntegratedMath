# 《综合数学》全书生产计划

著作人：Leo Lee

目标是逐批完成可以学习、练习和核验的教材正文。全量分类目录负责确定范围，生产台账负责记录实际完成了什么；两者不能互相替代。真实分类范围为 63 个部分、534 个章节、6006 个节项，其中 503 个通用文献节直接属于部分，5503 个专门节属于章节。保留原始归属，不另造章节凑数。

## 本轮产物与继续顺序

1. 保存现有第1章正文、题目与独立答案；旧审阅材料只能作为候选证据，须核对当前正文版本和具体覆盖范围。
2. 从 B1 计数与自然数运算、十进位值开始，落在第26章初等数论（11Axx）的基础桥接单元中。自然数单元明确采用自然数公理、归纳原则和递归原则；它不借尚未写成的 B3 数系构造证明自身。
3. 第二批已写自然数序、消去律与带余除法，位值表示的存在唯一性和相关算法的终止。第三批衔接自然数减法与书面加减，第四批已写整数的表示、加法、次序、乘法与符号规则；第五批已写整数带余除法、整除及最大公因数与欧几里得算法，第六批已写贝祖等式与互素性质。第七批已写有理数构造、加法、相反数与减法，第八批已写乘法与非零倒数除法；第九批接续有理数次序与绝对值距离；之后衔接等式、不等式、比例与单位；素数、唯一分解保留为数论支线，无需把它们作为有理数的强制前置。每次只交付定义、证明、例反例和题答均配套的可读单元，不以新标题数量衡量正文完成。
4. 完成 B2 函数与几何、B3 证明与离散基础后，再并行推进 B4 线性代数和单变量分析。B3 回访数系构造属于后续补强，不是反向施加给 B1 的隐含先修。
5. 按目标展开 B5、B6 及应用支线。每章开写前明确学习目标、精确先修和教学深度；未写章统一标记为“需规划”，不能统一降为导读。研究条目可以依据目标采用导读，但需逐项说明理由与后续完整证明所在。

第26章的自然数、位值单元仅为部分章草稿。它们不能代表整除、同余、素数、连分数等分类主题全部完成，也不自动授予任何 11Axx 子节的完成状态。基础单元在正文落实明确分类归属后，再逐项登记原有节号；不虚构新的 MSC 节。

## 台账与运行

```bash
python tools/build_production_ledger.py
```

仅依赖 Python 标准库，不访问网络。可用 `--root /path/to/book` 在另一完整工作副本中生成台账。生成器读取分类、中文版标题及 `LEARNING_PATH.md`，检查注册正文文件是否真实存在、是否非空，再生成：

- `data/production/parts.json`：63部分的真实归属、完整验收门槛及已核实推送记录。
- `data/production/chapters.json`：534章及其定位信息。
- `data/production/sections.json`：6006 节，保留503个直属部分条目。
- `data/production/units.json`：B1.1—B1.21、B2.1—B2.4的实际目标、采用规则、命题锚点、题答锚点与独立审核状态。
- `data/production/prerequisites.json`：B0—B6 模块规划、模块依赖、后续回访边及534章依赖规划状态。

这些 JSON 是可再生成的生产快照，不应直接手改来领取完成状态。当前正文注册集中在生成器的 `CH01`、`BRIDGE` 与逐章映射中；新增正文或审核登记前，先修改明确的注册和证据采集规则，再重新生成。没有自动扫描任意 Markdown 并充作已写正文的机制。

## 记录结构与完成标准

每章、每节都有 `code`、连续 `number`、中文 `title`、原始 `parent_code`、`part_code`、实际 `source_files` 和文件 SHA-256。正文不存在时文件数组为空；辅助答案或附录单独存在也不构成正文草稿。

`stage` 是当前可确认的写作状态；`stages` 独立登记 `unwritten`、`draft`、`math-reviewed`、`pedagogy-reviewed`、`build-verified` 的状态及证据。`coverage.completed` 只有全部既定教学目标完成且审阅证据齐备后才能为真。章节标题齐全、目录全覆盖、旧 PDF 构建成功都不是完成依据。当前生成器自动识别草稿，并仅导入通过文件哈希和范围核验的明确审核记录；不会根据报告文件存在自动批准审核。

每条记录还包含学习入口、入口诊断题、目标规划、逐目标深度、来源核验、已证／采用／外引／开放问题交叉引用、题答文件、题号配对检查以及审核证据。空字段表示工作尚待完成，不表示相应环节不需要做。

审阅升级必须记录审阅人、日期、范围、当前正文哈希、问题及处理结果；构建升级还需构建命令、输入输出哈希、公式与图像检查和实际截图检查。旧报告可以留在候选证据中，但不得因文件存在就标记为本次审核已通过。

## 先修图的边界

模块图是从现有学习路线展开的课程设计框架，已检查无环。它不是534章或6006节的完整精确先修图。各章的 `module_candidates` 只按分类给出选题定位，不能直接转成必修边。第1章仅有无前文章节先修的明确入口；其余章精确依赖仍待逐目标规划。

每次开写须把“掌握分析”等笼统要求改成可点开的章节、定义或命题锚点，并给出可检查的入口题。尚不存在的先修链接必须显示待写，不能伪装成可读内容。深造支线仅取需要的模块，不要求读完整个 B5 才能开始。数学史、数学教育与通用文献条目可以穿插阅读。

## 每批教材的审阅闭环

先冻结范围和学习目标，再核对先修与采用假设，随后完成教学正文、独立习题答案和必要数值代码。数学审阅检查条件、证明步骤、反例与循环依赖；教学审阅检查入口、定义与符号首次出现、例题梯度和答案可独立复核性。最后构建 Markdown/PDF，核对公式、图像、链接和题答对应，截图查看实际页面，并把证据绑定到本批源文件哈希。

所有来源逐项核对公开可得性及使用许可；“能阅读”不自动等于“能复制”。原创例题和改编题均记录来源与使用方式。前沿预印本须标明发表状态，未解决问题写“目前学界尚在研究”并记录核验日期。数值计算同时给出公式、条件、误差或稳定性说明、代码及可复现输入输出。本批公开来源核验记录见 `research/production/foundations_sources_2026-10-27.json` 及同名 Markdown 报告；只按其实际核验范围使用。

## 审核证据录入接口

数学与教学审阅由主编汇总到 `research/production/accepted_reviews.json`。顶层为 `{"schema_version":1,"reviews":[...]}`，每条记录遵循下列结构；下面的占位值不是可接受证据：

```json
{
  "target_type": "unit",
  "target_id": "b1-natural-numbers",
  "stage": "math-reviewed",
  "scope": "unit",
  "status": "accepted",
  "reviewer": "实际审阅人",
  "reviewed_at": "YYYY-MM-DD",
  "source_sha256": {
    "manuscript/foundations/natural_numbers.md": "实际SHA-256",
    "manuscript/foundations/natural_numbers_answers.md": "实际SHA-256"
  },
  "evidence": [{"path": "research/production/实际报告.md", "sha256": "实际报告SHA-256"}],
  "blocking_issues": []
}
```

B1.2 的 `target_id` 是 `b1-place-value`；教学审阅的 `stage` 是 `pedagogy-reviewed`。章节的 `target_type` 为 `chapter`、`target_id` 为原 MSC 章代码（如 `00Axx`）、`scope` 为 `registered_chapter_draft`。每条审核的 `source_sha256` 必须恰好覆盖目标当前全部 `source_files`，包括答案和已登记附录；证据文件也必须存在且哈希一致。字段缺失、版本不符或存在阻断问题时不授予审核状态。单位审核通过可显示为 `passed`；章节只显示所登记草稿范围的 `partial`，并不表示原分类全章内容完成。

单元审核通过会在第26章汇总为“已审这些单元”，不传播给未完成的原 MSC 节。源稿修改后旧哈希失配，状态退回待审；哈希只标识具体文本，不能代替审阅人对数学或教学质量负责。

构建报告来自 `data/production/batch_validation.json`。支持相同的 `validations` 数组结构，或构建器的 `source_sha256`、`artifact_sha256`、`checks`、`visual_review` 聚合结构。聚合报告须同时有实际 `command`，自动检查通过；视觉记录须有 `status="accepted"`、`result="passed"`、审阅人、日期、所看 PDF 的当前哈希，以及 `pages` 中按 PDF 路径列出的实际截图记录（每条含 `page`、`path`、`sha256`）。未实际看图或视觉记录缺失时保持待核验。源稿、产物或截图任一哈希过时均不升级。

录入后重跑生成器。每个台账的 `review_import_audit` 显示接受、拒绝或等待适配的逐项原因；`units.json` 分别展示实际审过的单元、范围和报告。当前正文仍可继续修订，生成时的哈希快照不宣称为最终定稿。

## 已展开的整数批次：从有条件自然数差进入整数

B1.6以后先写整数的表示和加法，随后再写整数乘法与整除；仍按第26章基础桥接单元安排，不改MSC目录。入口诊断是能解释自然数差的定义条件、加法消去律和带余分解条件，而不是预先会负数运算。

本批采用自然数对记录“增加量与减少量”，先定义两记录表示同一净变化的关系，证明自反、对称、传递；需要用到的有序对、关系、等价类均须当场定义，不默认为读者已学集合论。不能先借整数减法写出关系，再用该关系构造整数。采用这一形式构造，必须检查更换代表记录后加法不变；再解释零、正负、相反数及自然数嵌入。乘法与其代表无关性、符号规则和分配律已在B1.8接续单元逐项证明，不用“负负得正”口号替代。

每个单元仍分别保存正文和全解，登记已采用基础与已证结论、例反例、精确先修锚点、独立审读及编译证据。两份整数正文及其独立答案已经保存；数学、教学及构建状态以当前哈希绑定证据为准，不能据此把第26章或整数分类主题整体记作完成。


## 已展开的第五批：整数除法、整除与最大公因数

先教整除记号及“存在一个整数倍数”的含义，分清整除关系、整数商余与尚未定义的分数除法。把自然数商余定理扩展到整数被除数与正除数：负被除数必须分自然余数为零和非零两支，写出新商和非负余数，再证明唯一性，不能把计算机截断除法的符号约定默认成数学定理。若扩到负除数，先定义绝对值并证明其需要的性质；除数零明确排除。

随后建立公因数、最大公因数与欧几里得算法。每次更新须证明公因数集合保持，余数严格下降保证终止；零输入、双零的约定要提前说明。是否在同一单元加入贝祖等式，按先修与证明篇幅另作具体规划，不把尚未完成的证明压成结论列表。分数的约分只能在所需整除结论可读以后使用。B1.9—B1.11六份正文／答案已保存，每单元8题。采用非负规范与整除泛性质统一定义gcd，双零输出0；不把它解释成通常大小意义下的最大正公因数。贝祖等式未收入本批，独立审查状态仍须绑定当前实际源稿。
